## #2：构建复现

- 固定 SDK、最低系统版本和干净编译环境，精确检查编译器完整版本及链接器版本。
- 遍历可用工具链，避免不匹配的 Command Line Tools 遮蔽匹配的 Xcode。
- 可使用 `--developer-dir` 指定工具目录，不修改系统的 xcode-select 设置。
- 新手检查复用同一选择逻辑，不再只按编译器主版本判断。
- `--rebuild-check` 在 work 下重新编译，即使原组件已存在也不跳过；不覆盖组件。
- 本机已复现原审核组件的 SHA-256；其他电脑仍需独立验收。

已验参考：Xcode 26.6 / build 17F113，Apple clang 21.0.0
(clang-2100.1.1.101)，SDK 26.5，linker 1267，最低系统 26.0。
已存在且通过校验的组件无需重新编译。

## #5：TCC 草稿根的 `com.apple.macl`

在一台 macOS 26.7 机器上复现了 Issue #5：源首页索引没有 `com.apple.macl`，
但在受保护草稿根中新建的临时索引被系统自动附加 72 字节 `com.apple.macl`；
quarantine 保持逐字节一致，provenance 仍按既有规则记录。发布流程现在只接受这个
“源无、目标由系统新增 72 字节值”的单向情形。已有 macl 被删除或改写、错误长度、
quarantine 变化及其他未知属性仍会拒绝。合成草稿随后完成登记、原生保存和冷重开回读。

没有取得并验证反馈中的另一个官方 11.5.0 发行包，因此没有加入其指纹，
也没有宣称兼容。官方签名有效不等于接口兼容；仍需单独检查及原生验收。

## #5：首页登记

首页索引内容和扩展属性先完成准备，再把草稿移到最终位置。
提交前再次核对临时索引内容、属性和原索引，避免使用被改变的准备结果。
失败时保留 `failure.json`，记录所处阶段、索引是否已替换和建议恢复动作。
不自动删除临时文件、不覆盖被用户改过的草稿。

- 最终目录尚未创建：处理原因后重新 publish，使用新的审计目录。
- 草稿已落位、索引未替换：核对现场后 resume-publish。
- 索引已替换但后续检查失败：先检查和 verify，不声称已回滚。

本机原索引未携带反馈中的 `com.apple.macl`。尚无足够证据定义其安全转换规则，
因此这类差异仍会拒绝，并显示具体属性名。没有关闭 SIP/TCC 或移除安全属性。
本次修复失败次序和恢复诊断，不等于反馈环境的权限问题已经解决。

## #6：本地字体

本地整合了贡献者 wanchenxing 的
[PR #7](https://github.com/mcncarl/jianying-headless/pull/7)，来源提交
`a372d27ba35f1abe57d40244719d54b41faa85ae`；没有执行远端合并。
字体能力、可选依赖和限制见 [本地字体](LOCAL-FONTS.md)。

补充了默认速度省略的严格回读规则：仅速度素材中已知的普通 1 倍速度，
不扩展到曲线速度、片段速度、其他默认数值或非 1 倍速度。
41 项字体专项测试通过，使用真实字体和模拟的草稿 IO；这不是原生界面验收。
真实 IG 案例已完成新建、首页登记、完整播放、正常退出、冷重开及结构回读：
50.233333 秒、23 轨、154 段、39 素材、109 段文字、两份草稿内字体。
原始字体输入在构建后移到保留目录；原路径不可用时，仍通过重开和原生导出。
导出为 1080×1920、30 fps、1507/1507 帧，完整解码通过，来源 build 未改变。
抽帧确认可见人物、补充画面和文字，但不声称与 Hypit 原版逐像素一致或声音主观验收完成。
新建验收用系统静态 Arial / Arial Bold，字体文件未加入源码或公开附件。
独立编辑副本把 109 段文字改为 Monaco，输入字体原路径不可用后，
构建验证、首页登记、原生打开、保存、冷重开和最终回读均通过。
该副本也导出完整 1507 帧并通过完整解码，抽帧可见字体变化；源工程未改变。

原生保存会重建部分图片片段的空音频辅助节点编号，并重新填写设备标记。
回读仅在已审核的 11.5.0 / 187.0.0 范围内，对同类、无参数、单次引用、
一一对应的节点编号，以及限定设备标记做比较归一化；只改内存副本，不改原始证据。
版本、内容、参数、共享引用和非法设备标记仍拒绝，报告只记录设备字段名而不泄露值。
