# 两次真实口播剪辑后的 Token 成本复盘

## 背景

本次改动来自两条真实口播视频的交付，不是样例推演。两条源片都来自 iPhone，为 4K HEVC Main 10 HLG，并带有旋转元数据。

- 第一次：原片 5 分 22 秒，1.12 倍速，中度口播精简，单行中文字幕，无 BGM，无音效。交付 3 分 12 秒，16 个视频片段，90 条字幕。
- 第二次：原片 5 分 32 秒，1.15 倍速，精简口播，无字幕，无 BGM，无音效。交付 2 分 43 秒，16 个视频片段。

## 发现的浪费

Token 的大头不是生成草稿这个最后动作，而是重复观察、贴回大段转码日志、为了绕过“必须有字幕”的限制而先做占位字幕再删轨，以及在已有成熟会员能力时仍用 Agent 重做通用功能。

第二次视频明确不需要字幕，但原编译器强制字幕非空。为完成交付，当时只能提供占位字幕，编译后再用额外脚本移除文字轨。这是一个可以用产品边界消除的往返，不应该由更多 Token 来弥补。

## 与剪映会员的分工

使用者这次在闲鱼购买剪映 SVIP 的实际支出是每月 15.8 元。这是一次个人购买记录，不是官方定价、长期固定市价或购买建议。

当每天处理 10 到 20 条视频时，最合理的分工不是让 Codex 代替剪映的所有成熟功能：

- Codex 处理需要判断的部分：删掉口头禅、重说和无效停顿，守住数字、产品名和核心判断，生成可编辑草稿。
- 剪映 SVIP 处理成熟的通用功能：语音转文字、字幕样式和人工快速校对。
- 人处理最终审美和风险：通看切口、语义、画面和字幕，并在剪映里保存后冷重开验收。

如果任务不需要语义精简，或只是变速与自动字幕，直接使用剪映更省成本。只有删留判断、批量一致性或可追溯交付带来的价值高于 Agent 成本时，才让 Codex 进入流程。

## 本 PR 的改动

1. 无字幕成为原生分支。输入 `"subtitles": false` 后，编译结果保留空字幕列表，草稿不创建文字轨，也不输出空 SRT 和转写稿。
2. 增加素材预检和标准化入口。先检查编码、像素格式和旋转元数据，只在需要时转为 H.264 8-bit 4:2:0 与 AAC。
3. 转码默认安静。不再把每帧进度塞进对话，成功时只返回路径、hash、时长和尺寸摘要。
4. 保留兼容性。有字幕的原流程继续生成文字轨、SRT 和剪后转写稿。

## 成本结论

仓库无法从两次对话中取得可审计的精确 Token 计量，因此不给出伪精确的“每条节省百分比”。这次优化的验收标准是更可验证的三件事：无字幕任务少一次占位与删轨往返，不兼容素材少一轮错误定位，转码过程不再向上下文注入大量进度文本。

后续要评估真实节省幅度，应在同一类视频上记录源片时长、精简强度、工具往返次数、总 Token 和人工验收时间，再比较修改前后中位数。
